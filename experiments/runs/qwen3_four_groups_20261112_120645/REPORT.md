# Qwen3 8B 四组参数对照实验

共完成 4 组 × 3 个种子 × 每题 8 次提案 = 96 次本地模型请求。使用与上一轮相同的 n4_219 题目，4 个节点、4 条干预观测、8 个合法图。该题来自官方生成器，属于开发用单题实验。

公共配置为 qwen3:8b、Q4_K_M、num_ctx=4096、num_predict=2048、top_k=20、min_p=0、repeat_penalty=1。三个种子为 33550336、33550337、33550338，每轮的 8 次请求使用相同的轮次种子。组间及种子间清空历史。每次请求均由官方 create_prompt 根据之前成功解析的候选重建用户消息，包括无效候选。无额外 system 提示。思考组仅将 message.content 送入评分器，完整 message.thinking 保存在原始调用文件。

A 组在共同的 2048 输出上限下重新运行，上一次 64 上限的结果单独保留。所有请求共享候选次数及输出上限，实际 token 消耗与耗时单独记录。每次失败或截断仍消耗一个槽位，不增加模型重试。组顺序为每个种子依次 A、B、C、D，耗时可能受到加载、缓存及运行顺序影响。

## 平均表现

VR（有效率）= 满足全部观测的提案次数 / 8；NR（唯一率）= 不同的可解析图数 / 8，其中可能包含错误图；RR（恢复率或覆盖率）= 找到的不同合法图数 / 本题全部 8 个合法图。先逐轮计算，再对三个种子求均值，不能把三轮找到的图合并后当成这里的 RR。

均值和标准差均按三个种子计算，标准差不是置信区间。A 组采用温度 0，三个种子的运行不构成三个独立随机采样证据。

## 评分与完整记录

全部 96 次提案均使用固定版本官方因果图解析器和评测器，同时独立计算可达关系、不同边集和恢复的合法图进行核对。错误类型、重复次数、截断、空答案及逐次覆盖情况存入 summary.json 和 all_calls.csv。

config.json 保存公共配置、模型摘要、版本与脚本哈希。各 group_seed 子目录保存逐次 request、response、完整思考文本、耗时和官方结果。instance.json 包含题目和完整标准答案，标准答案不进入请求。runtime_gpu.json 保存运行时模型装载状态。

本结果限定于一题三个种子，不代表总体模型能力或统计显著性。B−A 对比温度影响，C−B 对比该共同采样配置下思考模式的影响，D 是另一套非思考配置。

## 结果解读与下一步

本轮暂以 B 作为后续方法改进的基线：其平均 RR 为 20.83%，高于 A 的 12.50% 和 D 的 16.67%。B、D 的平均 VR 均为 70.83%，但三个种子的 VR 都是 100%、100%、12.5%，波动很大。因此尚不能声称 B 在更广泛数据上优于 D，也不能把温度升高直接等同于稳定提升。

所有正常输出均成功解析。A 的 24 次调用有 21 次错误图；B、D 各有 7 次错误图。同一轮内重复之前图的次数，A、B、D 分别是 18、18、19 次（重复可能正确，也可能错误）。典型错误图为 `A->B, A->C, B->D, C->D`，它缺少 B 到 C 的路径，违反 Perturb(B) 对 C 的观测。典型正确图 `A->B, B->C, C->D` 则被多次重复。因此，正确性和不同合法解的覆盖需要分别优化。

C 的 24 次调用全部生成了思考文本，但都在 2048 个输出 token 上限处截断，最终答案为空；其 0 分表示当前预算下没有交付可评分的图，不表示思考模式没有推理能力。累计输出 token 为 49,152，请求耗时约 610 秒。无可解析答案时官方历史不更新，轮内又使用固定种子，因而会重复相同提示并可能重复相同思考轨迹。这些请求不能视为 24 次独立随机探索。

四组累计请求耗时 630.29 秒，输入 token 35,326，输出 token 50,364，合计 85,690。输出 token 包含思考文本；虽然输出上限相同，实际 token 消耗并不相等。耗时包含模型加载，且实验顺序固定，因此 B 与 D 的几秒级耗时差不能用来断言谁更快。

下一步建议优先研究“观测一致性验证 + 具体错误反馈 + 重复检测”。例如候选违反 B 到 C 的可达关系时，将这一可由题面计算的反例反馈给模型；发现重复图时，明确要求改变边集并重新验证。反馈仅依据观测和已生成候选，不读取标准答案。新增调用必须计入同等请求或 token 预算，避免用额外算力制造不公平提升。此方法尚未在本轮实现或验证。

思考模式应另做输出预算消融，记录增大上限能否获得最终答案及其成本；不能把当前 C 与之后不同上限的结果混为同一组。选定方法后再用未参与调参的多道题验证泛化。本轮只是一题上的开发实验。

最终文件核验：12 轮、96 个原始调用、96 行逐次指标；官方与独立计分全部一致；输出 token 合计与官方记录一致；运行脚本 SHA-256 与配置记录一致。
